# PR 작성

작성 전에 현재 브랜치, 대상 브랜치, merge base, 변경 파일, 관련 커밋, 검증 결과를 확인한다. 확인된 저장소와 이슈 맥락만 사용하고, 해결되지 않은 세부 사항은 `확인 필요`로 표시한다.

리뷰어가 다음 내용을 이해할 수 있게 작성한다.

- 문제와 의도한 결과
- 실제 변경의 논리적 흐름
- 영향을 받는 인터페이스, 데이터, 권한, 호환성 경계
- 사용자가 보게 되는 명령어, 옵션, 설정, 경로, 출력의 변화
- 실행한 검증과 아직 검증하지 못한 항목
- 리뷰가 필요한 결정 사항과 위험 영역

저장소의 템플릿과 용어를 유지한다. 계약이나 결정을 실질적으로 명확하게 할 때만 다이어그램, 표, diff 일부를 추가한다. 작은 hunk가 마이그레이션, 삭제 경계, 공개 인터페이스를 결정한다면 전체 diff 대신 필요한 최소 hunk를 설명 옆에 배치한다.

기본 동작은 초안 작성이다. 사용자가 원격 변경을 명시적으로 요청하고 저장소와 provider를 확인한 경우에만 PR을 생성하거나 갱신한다. 변경 후에는 확인 가능한 PR 식별자와 링크를 반환한다. PR 생성 자체를 승인, 머지 또는 배포로 간주하지 않는다.
