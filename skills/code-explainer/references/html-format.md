# HTML 설명 문서 형식

HTML 산출물을 요청했을 때만 읽는다. 기본 응답을 HTML로 바꾸지 않는다. 템플릿은 문서의 배치와 동작을 제공하는 자체 작성 자산이며 특정 프로젝트의 분석 결과가 아니다.

## 유지할 시각 형식

- 종이색 `#f7f6f1` 배경, 본문 `#161714`, 보조 글자 `#686b64`, 경계선 `#d8d7d0`, 강조색 `#2250d9`를 유지한다. 외부 폰트·CDN 없이 본문은 시스템 고딕, 제목은 Georgia·바탕 계열로 표시한다.
- 최대 너비 1120px, 고정 상단 제목·가로 목차, 넓은 첫 화면의 큰 제목과 한 줄 결론, 상태 안내와 근거 기준을 유지한다. 기본 `data-layout="explainer"`는 왼쪽 보조 설명과 오른쪽 절 카드, `data-layout="plan"`은 최대 너비 960px의 넓은 본문과 구분선 중심이다. 구현 해설에는 전자, 장문의 설명에는 후자를 선택한다.
- 내용은 결론 → 필요한 배경 → 구조 → 실제 동작 → 한계 → 상세 근거 순서를 출발점으로 삼는다. 실제 질문에 불필요한 절은 삭제하고 목차도 함께 바꾼다. 핵심 한계는 본문에 남긴다.
- 긴 코드, 정확한 조건과 확인 기록은 설명적인 `<summary>` 아래에 둔다. 상세를 접어도 본문만으로 목적과 동작, 근거의 한계를 이해할 수 있어야 한다.
- 구조 변경이면 같은 축으로 전후를 비교하고 추가·이동·유지되는 책임과 범위 밖 경계를 표시한다. 과거 근거가 없으면 개념도 또는 미확인으로 표시한다. 도식의 화살표마다 실제 호출·데이터 전달·반환 중 의미를 명확히 한다.
- 모든 상태는 색과 함께 글자로 구분한다. 도식은 본문 크기에 가까운 글자를 사용하고 모바일에서는 재배치하거나 해당 영역만 스크롤한다.

## 템플릿 사용

[explainer.html](../assets/explainer.html)의 중립적인 안내 내용을 실제 조사 결과로 교체한다. 제목, 리비전·조회 기준, 설명과 근거를 갱신하고 필요 없는 절과 예시 도식을 제거한다. 설명용 모형을 실제 구현처럼 남기지 않는다. 새로운 절에는 고유 ID와 목차 링크를 함께 추가한다. 코드·외부 텍스트를 넣을 때 HTML 특수문자를 이스케이프한다.

단일 HTML로 저장한다. 인라인 CSS·목차용 JavaScript만 사용하며 데이터 조회, 인증, 추적, 자동 업로드는 넣지 않는다. 대상 코드의 파일·심볼·리비전은 상세에 적고 접근 가능한 원문 링크가 있으면 연결한다. 공개 산출물에는 비공개 주소·업무 데이터·로컬 절대 경로를 넣지 않는다. 링크만 주어진 비공개 자료는 읽지 못한 채 확인했다고 표시하지 않는다.

## 확인

원문과 조건·범위·확신 수준을 대조한다. 브라우저를 사용할 수 있으면 데스크톱과 390px 안팎의 모바일에서 제목 줄바꿈, 본문과 도식 글자, 정렬, 페이지 가로 넘침을 확인한다. 목차 이동 후 제목이 헤더에 가려지지 않는지, 현재 절 표시와 키보드 접기·펼치기가 동작하는지 확인한다. 자바스크립트가 없어도 본문·앵커·접기는 읽을 수 있어야 한다. 브라우저 오류와 외부 요청도 확인한다.

정적 형식 검사, 브라우저 확인, 설명 내용의 코드 대조는 서로 다른 증거다. 실행하지 못한 검사는 미검증으로 남긴다. HTML 저장 성공은 게시 성공을 뜻하지 않는다.
