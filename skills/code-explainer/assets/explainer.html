코드의 흐름을
어떻게 읽으면 될까요?

목적을 먼저 이해하고 실제 진입점에서 결과가 소비되는 곳까지 따라갑니다. 이 문서는 형식을 보여주는 템플릿이며, 특정 구현을 분석한 결과는 아닙니다.

한 줄 결론
독자가 궁금한 동작과 그 근거를 같은 흐름 안에서 설명합니다.
현재 상태: 설명할 코드를 아직 대입하지 않았습니다. 안내 문구를 실제 조사 결과로 바꾸고 미확인 범위는 그대로 밝힙니다.

읽는 순서

본문에서 동작을 이해하고, 펼치는 상세에서 코드와 조건을 확인합니다.

01 · 목적

사용자에게 무엇이 달라지나요?

기능이 해결하는 문제와 입력에 따라 보이는 결과를 적습니다. 내부 파일 목록부터 나열하지 않고 독자의 질문에 먼저 답합니다.

설명할 대상과 범위를 짧게 밝히고 범위 밖의 동작은 확인했다고 쓰지 않습니다.

02 · 구조

어디서 시작하고 누가 책임지나요?

실제 진입점과 중간 계층, 상태 소유자, 결과 소비처를 코드 근거로 연결합니다.

확인한 구현

읽은 파일·심볼과 실제 조건을 적습니다. 변경 전후 비교라면 같은 기준으로 나란히 배치합니다.

추론 또는 미확인

설계 의도를 추정한 이유와 아직 읽지 못한 경계를 구분합니다.

03 · 동작 흐름

입력은 어떤 순서로 결과가 되나요?

아래는 설명용 모형입니다. 실제 문서에서는 확인한 중간 호출·조건·반환을 넣고 분기나 생략을 명시합니다.

상태·비동기·실패 조건을 설명하는 방법

상태가 어디에 얼마나 오래 남는지, 무엇을 기다린 뒤 다음 동작이 시작되는지, 실패가 복구되거나 전파되는 조건을 적습니다. 코드에 없는 재시도나 순서 보장은 추가하지 않습니다.

04 · 한계

아직 무엇을 확인하지 못했나요?

코드를 읽어 확인한 내용과 실행 관찰을 구분합니다. 핵심 제한은 상세를 열지 않아도 이곳에서 읽을 수 있게 합니다.

미검증: 이 템플릿 자체는 분석 대상의 동작이나 테스트 결과를 증명하지 않습니다.

05 · 상세 근거

어떤 코드를 기준으로 설명했나요?

핵심 주장 가까이에 근거를 연결하고, 긴 목록은 이곳에 모읍니다.
