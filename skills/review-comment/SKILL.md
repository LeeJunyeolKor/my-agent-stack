# 리뷰 코멘트 작성과 게시

입력은 근거가 있는 리뷰 결과와 대상 위치다. 조사 전이거나 새로운 기술적 판단이 필요하면 code-review로 돌아간다. 기존 판단의 조건·심각도·확신 수준을 표현 편집 과정에서 바꾸지 않는다. [기술 문서 작성](../technical-writing/SKILL.md)의 의미 보존 기준을 적용한다.

## 초안

기본은 초안 작성이다. “댓글 문구만”, “다듬어줘”는 게시 요청이 아니다. 관찰한 사실과 발생 조건·영향을 먼저 쓰고 구체적인 제안을 이어 쓴다. 직접 확인한 사실과 예상 영향의 확신 수준을 구분한다. 본문은 이전 대화 없이도 이해할 수 있어야 한다.

전체 의견과 인라인 의견을 나누고, 인라인은 하나의 지적에 필요한 좁은 범위로 잡는다. diff 밖의 근거는 전체 의견에 경로와 함께 설명한다. 코드는 문장으로 대안이 분명하지 않을 때만 넣는다. 서명·문체는 저장소 규칙과 사용자의 요청을 따르며 사람 검수를 추정하지 않는다.

## 게시

사용자가 “달아줘”, “게시해줘”, “리뷰하고 달아줘”처럼 명시적으로 요청했을 때만 게시한다. 이미 받은 같은 범위의 승인을 반복해서 요구하지 않는다.

1. 저장소, PR, 현재 원격 head, 기존 댓글과 초안을 대조한다. 바뀐 코드에서 더 이상 유효하지 않은 지적은 제외한다.
2. 해당 제공자의 현재 API와 diff의 파일·이전/이후 줄을 확인한다. 다른 리비전의 줄 번호를 재사용하지 않는다.
3. 본문은 구조화된 인자나 본문 파일로 전달한다. 셸 코드에 직접 보간하지 않는다.
4. 응답의 ID·본문·위치를 확인한다. 결과가 불명확하면 댓글을 재조회한 뒤 재시도 여부를 판단한다. 시간 초과만 보고 다시 게시하지 않는다.
5. 요청한 위치에 반영됐는지와 남은 실패를 보고한다. 도구·권한이 없으면 초안만 제공하고 미게시로 표시한다.

수정 요청은 기존 ID를 대상으로 처리한다. 삭제·스레드 해결·답글은 각각 요청 범위에 포함됐을 때만 수행한다. 잘못된 전제가 발견돼도 기존 댓글을 다른 지적으로 바꿔 재활용하지 않는다.
