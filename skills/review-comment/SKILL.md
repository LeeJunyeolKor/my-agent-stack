# 리뷰 코멘트

실제 diff, 인접 계약, 관련 호출자와 소비자, 테스트, PR의 주장, 기존 논의를 검토한다. 조사 범위는 위험에 비례시킨다. 상수 변경은 주입과 사용 지점 확인만으로 충분할 수 있지만, 공유 인터페이스나 데이터 형식 변경은 하위 소비자까지 추적해야 한다.

결함과 선택적 개선 사항을 구분한다. 실행 가능한 모든 지적은 다음 흐름으로 연결한다.

```text
로컬 계약 → 관찰된 변경 → 구체적 위험 → 가장 작은 유효 수정
```

결론에 실질적인 영향을 주는 기술적 주장은 현실적인 확인 방법이 있다면 재현한다. 주장을 검증할 수 없다면 버그라고 단정하지 말고 집중된 질문을 하거나 증거 공백을 표시한다.

기본 동작은 코멘트 초안 작성이다. 인라인 범위는 좁게 유지하고 검토한 diff에 포함된 줄에만 피드백을 단다. 관련 계약이 diff 밖에 있다면 전체 코멘트를 사용한다. 글만으로 수정 방향이 모호할 때만 대안 코드를 포함한다.

사용자가 명시적으로 요청한 경우에만 코멘트를 게시한다. 게시 직전에 저장소, PR, 현재 diff 줄, 코멘트 본문을 다시 확인한다. 게시 후에는 반환된 식별자와 위치를 검증한다. API 성공만으로 의도한 위치에 인라인 리뷰가 등록됐다고 판단하지 않는다.
