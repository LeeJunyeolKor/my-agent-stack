# 용어 검토

코드 식별자, 공식 API 이름, 대상 저장소나 팀에서 일관되게 사용하는 도메인 용어는 유지한다. 일반 사전의 권장 표현보다 로컬 일관성을 우선한다.

설명용 영어, 어색한 직역, 같은 개념을 가리키는 여러 표현은 독자의 이해를 높일 때만 다듬는다. 생소한 라이브러리나 도메인 용어가 처음 나올 때 도움이 된다면 짧은 한국어 뜻을 덧붙인다.

팀에서 합의한 용어인지 추정하지 않는다. 용어를 바꾸면 해석이 달라질 수 있고 로컬 규칙이 불분명하다면 원문을 유지하고 확인 대상으로 표시한다.

수정 내용을 검토받아야 한다면 `원문 | 권장안 | 이유` 형식으로 제시한 뒤 근거가 있는 변경만 요청된 초안에 반영한다. 주변 문장을 편집할 때 소스 코드 식별자는 바꾸지 않는다.
