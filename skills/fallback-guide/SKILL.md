# 폴백 가이드

사용자가 범위를 확장하지 않는 한 작업을 클라이언트 측 폴백 책임으로 제한한다. UI, 데이터, 브라우저 API, 플랫폼 API의 성능 저하 상황을 다루되 서버 복구, 배포, 롤백, 인프라 동작을 임의로 만들지 않는다.

저장소 지침을 읽고 실제 코드에서 기존 폴백 경로를 찾는다. 다음 기준으로 가장 작은 문서 위치를 선택한다.

- 탐색 경로와 짧은 공통 규칙은 `AGENTS.md` 또는 README에 둔다.
- 상세 조건과 예시는 가장 가까운 기존 문서에 둔다.
- 관리되는 적절한 위치가 없을 때만 새 문서를 만든다.

문서화하는 모든 폴백에는 네 가지를 명시한다.

1. **조건:** 폴백을 유발하는 실패, 데이터 부재 또는 미지원 기능
2. **동작:** 사용자가 보게 되는 결과 또는 정상 경로를 대신하는 경로
3. **관측:** 로그, 지표, 알림 등으로 성능 저하 상태를 감지하는 방법
4. **검증:** 해당 동작을 입증하는 테스트, 빌드 또는 수동 시나리오

현재 저장소의 짧은 예시만 사용하고 경로를 함께 적는다. 가능하면 정상 분기와 폴백 분기를 함께 보여준다. 검증 수단이 없다면 입증된 것처럼 쓰지 말고 `검증 필요`로 표시한다.

중요한 실패를 감추는 무음 성공 폴백을 권장하지 않는다. 구현 변경을 요청받으면 호출자를 추적하고, 여러 곳을 반복해서 수정하기보다 하나의 공통 진입점을 우선한다.
