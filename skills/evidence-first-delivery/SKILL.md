# 증거 기반 완료 판단

현재 증거가 직접 뒷받침하는 결과부터 말한다. 각각을 검증하기 전까지 다음 상태를 서로 분리한다.

- 구현 존재
- 로컬 검사 통과
- CI 또는 파이프라인 검사 통과
- 리뷰 또는 승인 완료
- 변경 머지 완료
- 배포 완료
- 런타임 동작 검증 완료

결론을 내리기 전에 관련 범위를 확인하고 각 관찰이 무엇을 입증하는지 구분한다. 성공한 명령은 실제로 실행한 검사만 입증한다. 생성된 PR, 전송된 메시지, 작성된 양식, 예약된 레시피, 종료 코드 0만으로 승인, 머지, 전달, 복구 또는 런타임 성공이 입증되지는 않는다.

증거가 불완전하다면 결과에 다음 중 하나를 표시한다.

- **검증됨:** 현재 작업에서 직접 확인했다.
- **관찰됨:** 진행 경로나 중간 상태가 보이지만 결과는 입증되지 않았다.
- **추론:** 근거를 바탕으로 해석했지만 추가 확인이 필요하다.
- **알 수 없음:** 확인하지 않았거나 확인할 수 없다.

요청된 변경은 위험에 비례해 검증하고 실행한 검사를 정확히 보고한다. 사용자가 요청하지 않았다면 외부 시스템을 변경하지 않는다. 결론에 실시간 재확인이 필요하다면 과거 증거를 현재 사실로 바꾸지 말고 재확인이 필요하다고 밝힌다.
