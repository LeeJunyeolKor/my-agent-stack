# 환경 온보딩

설치를 제안하기 전에 대상 환경을 파악한다.

1. 사용자가 실제로 사용할 에이전트를 확인한다.
2. 소스 제어, 이슈 추적, 메시징, 스케줄링 등 필요한 capability를 사용 가능한 provider 또는 `none`에 매핑한다.
3. 필수 capability가 충족되는 스킬과 자동화 레시피만 선택한다.
4. 대상 경로, 권한, 호환되지 않는 모듈, 축소되는 선택 기능을 미리 보여준다.
5. 설정을 기록하거나 외부 시스템 변경을 활성화하기 직전에 확인을 요청한다.
6. 설치된 파일을 검증하되, 파일 복사가 동일한 런타임 동작의 증거라고 간주하지 않는다.

회사별 값은 Git에서 제외된 로컬 프로필에 둔다. 인증 정보, 내부 URL, 티켓 데이터, 저장소 내용, 비공개 정책, 복사한 업무 산출물을 이식 가능한 스택에 옮기지 않는다. 결과 설정을 설명할 때는 합성 예시를 사용한다.

초기 설정은 읽기 전용을 우선한다. 새 환경에서 런타임, 권한, 실패 동작, 사람의 승인 지점을 검토하기 전까지 자동화 레시피를 비활성 상태로 유지한다.
