# 기술 문서 작성

독자는 개발 지식은 있지만 이번 변경과 대화는 처음 접하는 사람으로 잡는다. 설명할 대상과 결과를 먼저 밝히고, 그 판단에 필요한 이유와 근거를 이어 쓴다. 산출물의 섹션·템플릿은 대상 저장소 규칙과 해당 산출물 스킬을 따른다.

## 의미를 보존하는 편집

- 초안 작성과 문단 수정 모두에 적용하되, 오타 하나를 고치는 요청을 문서 전체 재작성으로 확대하지 않는다.
- 조건, 범위, 단위, 수치, 부정, 원인과 결과, 확신 수준을 원문과 대조한다. 짧게 쓰려고 이를 생략하거나 추론을 사실로 바꾸지 않는다. 직접 인용과 코드 식별자는 유지한다.
- 결론·제약의 이유를 가까이 적는다. 여러 모듈의 변경이면 각 역할과 실제로 필요한 적용 순서를 밝힌다.
- 문단마다 하나의 판단을 다룬다. 긴 설명은 필요한 맥락을 본문에 남기고 기존 상세 문서로 연결한다. 비교는 같은 기준의 표로, 순서는 목록으로 표현하되 같은 내용을 반복하지 않는다.
- 명사만 이어 붙이기보다 누가 무엇을 어떻게 바꾸는지 동사로 쓴다. 지시어의 대상이 멀면 정확한 대상을 다시 적는다.

## 용어

공식 API 이름, 파일 경로, 코드 식별자와 저장소에서 일관되게 쓰는 도메인 용어를 보존한다. 설명용 영어와 직역은 뜻이 더 명확해질 때 한국어로 고친다. 낯선 개념은 첫 등장에 필요한 만큼만 설명한다. 팀 합의나 용어사전을 새로 만들어 강제하지 않는다.

측정값은 대상·기간·단위가 드러나게 표현한다. 고정 구간과 이동 구간, 전체와 표본처럼 해석을 바꾸는 차이는 그대로 남긴다.

독립적인 교정 요청이면 수정본과 의미에 영향을 주는 이유를 제시한다. 고칠 곳이 없으면 그대로 알린다. 다른 산출물 작성 중에는 결과를 초안에 반영한다. 사실이 불확실하면 문체만으로 단정하지 말고 확인할 사실을 표시한다. 게시 권한은 이 스킬이 부여하지 않는다.
