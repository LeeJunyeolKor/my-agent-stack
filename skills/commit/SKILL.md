# 커밋

모든 커밋 메시지는 현재 `git status`, 스테이징된 diff와 스테이징되지 않은 diff, 저장소 지침, 실제로 실행한 검사를 근거로 작성한다. 티켓 제목이나 대화만 보고 변경 내용을 추정하지 않는다.

요청 범위를 명확히 구분한다.

- 미리보기나 메시지만 요청한 경우 스테이징하거나 커밋하지 않는다.
- 스테이징된 변경만 요청한 경우 스테이징되지 않은 파일을 추가하지 않는다.
- 단일 커밋 요청은 사용자가 지정한 단위를 하나로 유지한다.
- 그 외에는 서로 독립적인 변경을 리뷰 가능한 논리적 단위로 나눈다.

커밋 전에 저장소의 메시지 규칙과 훅을 확인한다. 저장소 구조가 뒷받침할 때만 패키지나 애플리케이션 이름을 scope로 사용한다. 훅이 이슈 식별자를 자동으로 추가한다면 중복해서 넣지 않는다. 저장소가 식별자를 요구하지만 확인할 수 없다면 임의로 만들지 말고 사용자에게 묻는다.

변경 범위와 위험에 비례하는 검사를 실행한다. 실패한 훅을 `--no-verify`로 우회하지 않는다. 의존성이나 훅 실패는 사용자 승인 없이 설치, 재설정, 보호 장치 생략을 허용하지 않는다.

승인된 커밋을 만든 직후 `git log -1 --oneline`으로 확인하고, 커밋과 통과한 검사를 함께 보고한다. 커밋되지 않은 변경과 관련 없는 사용자 변경은 그대로 보존한다.
