# 검증 계약

다음 명령을 실행합니다.

```bash
npm run verify
```

현재 이 명령은 다음 항목을 검사합니다.

- JavaScript 문법과 JSON 파싱
- 구성 요소, 에이전트, 프로바이더, 엔트리포인트, 이름 규칙의 불변 조건
- 필수 기능 확인과 명시적 제외 처리
- 결정론적 설치 계획과 파일 해시
- 임시 디렉터리에 선택한 항목만 설치되는지 여부
- 동일한 재설치의 멱등성
- 충돌 및 심볼릭 링크 경로 이탈 거부
- 자동화가 기본적으로 비활성화되는 안전장치
- 공개 안전성 패턴
- README의 카탈로그 항목 포함 여부

<a id="evidence-boundary"></a>
## 증거의 경계

검증을 통과했다는 것은 현재 체크아웃의 카탈로그와 로컬 설치 도구가 테스트 대상 계약을 충족한다는 뜻입니다. 다음 항목까지 증명하는 것은 아닙니다.

- 목록에 있는 모든 에이전트에서 동작이 동일하다는 것
- 실제 프로바이더 연결이나 인증이 성공한다는 것
- 자동화가 예약 또는 활성화되었거나 유용한 결과를 만들고 있다는 것
- 조직 정책을 검토하지 않아도 안전하게 사용할 수 있다는 것
- 공개된 패키지 레지스트리에서 설치할 수 있다는 것

해당 에이전트와 구성 요소 버전에 대해 현실적인 독립 동작 테스트가 기록되기 전까지 대상 호환성은 `unverified`로 유지합니다.

## 플러그인 검증 단계

1. 형식·정적 검사: SKILL frontmatter, 카탈로그 이름·의존성, JSON, 허용 파일과 상대 참조를 검사한다. 이것은 모델의 판단을 검증하지 않는다.
2. 자동화 테스트: 임시 디렉터리에서 동일 빌드·변경된 캐시 버전·교체 승인·추가 파일·심볼릭 링크·위험 내용 차단·기존 별칭·티켓 없는 선택 설치를 검사한다.
3. 패키지 검사: `npm run plugin:build` 후 `npm run plugin:verify`로 현재 원본과 산출물 전체 해시가 같은지 검사한다. 공식 plugin-creator 검증기는 별도로 실행한다.
4. Codex 실동작: 로컬 설치 후 새 작업에서 발견·호출과 관찰 가능한 부작용을 확인한다. 조직 플러그인 공존도 이 단계에서 확인한다. 실행하지 못한 시나리오는 미검증으로 남긴다.

대표 시나리오는 메시지만 요청했을 때 index·HEAD 불변, 리뷰만 요청했을 때 코드·댓글 불변, 티켓 없는 PR 초안, 조회 실패를 누락으로 표시한 보고서, 없는 도구의 미실행 표시다. 문자열 일치 테스트로 이 행동을 통과 처리하지 않는다. 실제 실행 기록은 [로컬 검증 결과](validation-results.md)에 따로 적는다.

코드 설명은 짧은 함수의 범위, 여러 계층의 중간 호출, 비동기·실패 조건, 의도 추론과 도구 부재, 설명 전후 파일·index·HEAD를 새 Codex 작업에서 확인한다. 명시 호출 성공과 자연어 자동 선택의 결과를 구별한다. HTML 템플릿의 데스크톱·모바일 배치, 목차·접기·콘솔 확인은 모델 행동 검증과 별도로 기록한다. 0.3 결과는 [코드 설명 검증](code-explainer-validation.md)을 따른다.
