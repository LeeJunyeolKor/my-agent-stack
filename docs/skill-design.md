# 스킬 역할과 출처 판단

기존 이식형 스킬을 중심으로 판단 기준을 보강했다. 참고 자료의 제품명만 바꿔 복사하는 방식은 사용하지 않는다. 프로젝트별 규칙은 작업 대상의 AGENTS.md, 템플릿, 설정에서 확인한다.

| 기존 역할 | 유지 | 보강 | 반입하지 않는 내용 |
| --- | --- | --- | --- |
| commit | diff 근거, 메시지만·staged만 범위 | 실제 훅 내용 확인, 티켓 없는 작업, 미실행 명시 | 조직 커밋 타입, 고정 티켓 형식, 자동 인증·훅 복구 |
| pull-request | 변경·검증에 근거한 초안 | 조회와 작성 분리, 사용법 전후 비교, 검증의 보장 범위 | 조직 템플릿, 고정 제목, 전용 API 래퍼 |
| review-comment | 근거와 위험, 요청한 게시만 실행 | code-review로 조사 분리, 최신 리비전·위치·중복 확인 | 조직 서명, 전용 도구 강제, 실제 업무 예시 |
| terminology-review | 로컬 용어·식별자 보존 | technical-writing으로 확장, 조건·부정·인과·확신 보존 | 내부 용어사전과 실제 PR 예시 |
| fallback-guide | 조건·동작·관측·검증 | 소유 문서 하나와 실제 저장소 예시 | 회사 코드·이미지 주소·서버 복구 추정 |
| evidence-first-delivery | 주장과 증거의 경계 | report-writing에 기간·집계·저장 분리 | 내부 게시 플랫폼과 업무 보고 내용 |

기존 용어 스킬은 별도 참조 문서나 소비 스킬의 연결이 없는 독립 스킬이었다. 최신 요구는 용어 교체보다 넓은 의미 보존과 구성 기준이므로 `technical-writing`으로 이름을 확장했다. 공통 작성 기준은 이 스킬 한 곳에 두고, 소비 스킬의 `dependencies`로 함께 설치한다. `catalog/stack.json`의 별칭은 이전 프로필의 선택을 해석한다. 이름이 바뀌었다고 기존 설치 폴더를 삭제하지 않는다.

`code-review`는 조사·타당성 판단을, `review-comment`는 판단이 끝난 초안의 표현·게시를 담당한다. 보고서도 증거 수준은 `evidence-first-delivery`, 기간·집계·구성·저장은 `report-writing`이 소유한다.

## 출처와 저작자

`code-explainer`는 코드 조사와 동작 설명을 담당한다. `technical-writing`만 설치 의존성으로 연결하며 `code-review`의 결함 판단과 `report-writing`의 집계 절차는 가져오지 않는다. 설명 요청만으로 파일·index·HEAD를 바꾸지 않고, HTML 작성 요청은 해당 산출물의 저장 범위로 해석한다.

설명형 문서 참고 스킬은 별도 작업 브랜치에서 최초 추가와 후속 수정 이력을 확인했다. 별도 참조·스크립트나 명시된 외부 출처는 없었고, Git 작성자만으로 원저작자·재배포 권한을 확정하지 않았다. 사용자 지정 HTML 두 문서도 본문·스타일·화면을 읽어 정보 배치와 동작을 확인했다. 원문·코드·업무 예시를 반입하지 않고 코드 조사 절차와 HTML/CSS/JavaScript를 새로 작성했다. 종이색·강조색·타이포그래피·목차·본문과 상세의 배치가 형식의 기준이다. 내부 출처 주소나 작성자 정보는 공개 저장소에 기록하지 않는다.

Git의 최초 추가 커밋 작성자는 파일을 저장소에 넣은 사람이다. 원저작자나 재배포 권한을 자동으로 증명하지 않는다. 참고 자료의 추가 이력과 명시적 출처·라이선스를 확인했지만, 상위 저장소의 공개 재사용 허락을 확정할 자료는 확인하지 못했다. 따라서 본문·참조·스크립트·예시·이력을 반입하지 않고 일반적인 의사결정 기준을 이 저장소에서 새 문장과 구조로 작성했다.

이 저장소의 `provenance.origin: generalized`는 경험을 일반화했다는 분류이며, 제3자 원문의 저작권을 취득했다는 뜻이 아니다. MIT 표기는 이 저장소의 작성물에 적용된다. 저작권·출처가 불분명한 템플릿, 예제, 스크립트는 가져오지 않는다. 앞으로 외부 자료를 반입하려면 원문 위치·버전·라이선스·원저작자·수정 범위와 필요한 고지를 먼저 기록한다. 비공개 출처의 경로나 인명은 공개 메타데이터에 넣지 않는다.

플러그인 형식은 [OpenAI의 Build plugins](https://learn.chatgpt.com/docs/build-plugins)와 설치된 plugin-creator 스키마를 확인해 작성했다. 실제 스킬은 이 저장소의 `skills/`만 사용한다. 다른 저장소의 플러그인 빌드 코드나 Git 이력을 복사하지 않는다.
