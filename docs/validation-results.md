# 로컬 검증 결과

`code-explainer`의 0.3 설치 버전·29개 자동화 테스트·브라우저·새 Codex 행동 검증은 [코드 설명 검증](code-explainer-validation.md)에 기록했다. 아래 내용은 0.2 당시의 스냅샷이다.

검증일: 2026-09-17. Node.js v26.6.0, Codex CLI 0.154.0 환경에서 확인했다. Node.js 20과 다른 운영체제는 별도 실행하지 않았다.

| 단계 | 확인한 내용 | 결과 |
| --- | --- | --- |
| 형식 | JavaScript·JSON, 카탈로그, 스킬 11개 frontmatter, 공식 plugin-creator manifest 검증 | 통과 |
| 자동화 | 기존 설치와 패키징·별칭·의존성·dry-run·경로·충돌·검사 실패 처리 | 27개 통과 |
| 패키지 | 26개 포함 파일, 상대 참조, 원본과 전체 해시, 추가 파일 감지 | 통과 |
| 비공개 정보 검사 | 저장소와 생성 패키지에 일반 패턴 및 로컬 전용 표식 검사 | 발견 사항 없음 |
| 로컬 설치 | 마켓플레이스 등록, 플러그인 설치·활성 상태, 내용 변경 후 재설치 | 통과 |
| 새 Codex 작업 | 설치 캐시의 11개 스킬 발견·읽기, 명시적 한정 이름 호출 | 확인 |

검사에서 발견 사항이 없다는 것은 검사한 패턴과 범위의 결과다. 모든 비공개 정보가 자동으로 탐지된다는 뜻은 아니다. 회사 원본의 코드·템플릿·참조 자료·Git 이력은 반입하지 않았다.

## 실제 행동 시나리오

별도의 티켓·원격 없는 예제에서 GPT-6 Astra / high로 실행했다. 자동화 테스트와 모델 행동의 근거를 섞지 않는다.

| 요청 | 실제 관찰 |
| --- | --- |
| 커밋 메시지만 | diff에 근거한 메시지만 작성, 스테이징·커밋 없음 |
| 리뷰만 | 폴백 연산자 변경의 동작 차이를 재현, 입력 계약이 없어 결함 단정 보류, 수정·게시 없음 |
| 티켓 없는 PR 초안 | 티켓을 요구하지 않고 초안 작성, 원격 대상·merge base 미확정 명시 |
| 일부 조회 실패 보고 | 성공한 두 소스의 8건만 집계, 실패한 소스는 제외, 재조회는 계획으로 구분 |
| 게시 도구 없는 댓글 | 조건부 판단을 유지한 초안, 게시 불가·미게시 명시 |

검증 전후 예제의 HEAD, index SHA-256, 파일 내용·diff와 Git 상태가 동일했다. 기존 조직 플러그인이 설치·활성화된 상태에서 My Agent Stack 11개와 조직 스킬 15개가 함께 발견됐고, 한정 이름으로 지정한 지침을 설치 캐시에서 읽었다. 기술 문서 작성과 증거 판단 의존 지침도 확인했다. 모든 자연어 요청에서 올바르게 자동 선택된다는 뜻은 아니다.

최초 호출 버전은 `0.2.0+content.d4cfb0da88441f4d`다. 최종 스키마 JSON의 형식 정리 후 설치 버전은 `0.2.0+content.ab8d9922dade2eba`이며, 11개 SKILL.md의 SHA-256은 전부 같다. 변경된 패키지 파일은 구성 요소 스키마와 캐시 버전을 담은 plugin.json뿐이다.

## 남은 제한

- 일반 자연어의 자동 스킬 선택 정확도와 반복 실행 안정성은 통계적으로 검증하지 않았다. 명시적 한정 이름을 사용한다.
- 실제 원격 PR 생성·댓글 게시·이슈 변경·보고서 업로드는 실행하지 않았다.
- 복구용 remove 후 재설치 절차는 현재 CLI 도움말과 빌드 재설치로 확인했으나 실제 제거는 실행하지 않았다.
- 모든 스킬·모든 에이전트의 동작을 검증한 것은 아니므로 카탈로그 targets는 unverified를 유지한다.
- 공개 디렉터리 등록과 GitHub 직접 플러그인 설치는 범위에 포함하지 않는다.
