# 코드 설명 스킬 검증

검사일: 2026-09-17. 구현과 새 Codex 검증 작업은 GPT-6 Astra / high를 사용했다. 병렬 하위 에이전트는 사용하지 않았다.

## 형식·설치·패키지

- `npm run verify`: 자동화 테스트 29개 통과, 카탈로그 12개 스킬·3개 레시피·6개 에이전트 및 공개 안전성 검사 통과.
- skill-creator의 `quick_validate.py`와 plugin-creator의 `validate_plugin.py` 통과.
- `plugin-build --dry-run` 후 재생성, `plugin-verify` 통과. 마켓플레이스 포함 30개 파일이며 스킬 원본과 상대 참조를 검사했다.
- 선택형 설치는 티켓 프로바이더 없이 `code-explainer`와 `technical-writing`을 설치하고 HTML 바이트를 보존한다. 누락된 HTML 앵커·파일, 패키지 밖 참조와 임의 추가 자산은 자동화 테스트에서 거부했다.
- 로컬 설치 버전은 `0.3.0+content.03a62ee0644e93ac`. 생성된 플러그인 29개 파일과 설치 캐시의 전체 경로·해시가 일치했다.
- 이전 워크트리의 마켓플레이스 등록을 새 빌드 루트로 옮겼다. 다른 플러그인 설정은 변경하지 않았다.
- 새 스킬과 전체 배포 파일에서 조직명·내부 도메인·실제 업무 식별자·인증 표식·사용자 절대 경로를 별도로 검색해 검출되지 않았다. 패턴 검사가 모든 민감 정보를 탐지한다고 보장하지는 않는다.

## HTML 화면과 동작

지정된 두 참고 문서의 실제 HTML과 화면을 확인한 뒤 스타일과 구현을 새로 작성했다. 종이색 배경, 파란 강조, 바탕 계열 큰 제목, 고정 상단 목차, 결론·상태·근거 줄, 본문과 상세 접기를 반영했다. 카드와 보조 설명을 쓰는 `explainer`, 넓은 본문과 구분선을 쓰는 `plan`을 제공한다. 업무 내용과 원문의 HTML/CSS/JavaScript를 가져오지 않았다.

Chromium에서 두 레이아웃 모두 1440px·390px로 확인했다. 페이지 가로 넘침이 없고 목차 이동·현재 절 표시·키보드 상세 펼치기와 접기가 동작했다. 문서 끝까지 스크롤된 경우 마지막 절을 현재 위치로 표시한다. 일반 스크롤의 부드러운 이동과 동작 줄이기 설정을 확인했고, JavaScript 비활성 상태에서도 본문·앵커·상세 접기를 사용할 수 있었다. 페이지 스크립트 오류와 외부 네트워크 요청은 없었다. 데스크톱·모바일 캡처로 제목, 본문과 도식의 가독성을 확인했다.

## 새 Codex 작업에서 관찰한 행동

설치 후 새 작업에서 플러그인 목록의 스킬 발견과 캐시 지침 읽기를 확인했다. 설명용 작은 JavaScript 프로젝트에는 표시 함수, 주입받는 통신 어댑터, 모듈 수준 캐시, 뷰별 요청 번호와 render 콜백을 두었다. 정답이나 예상 결함을 전달하지 않고 소스와 현실적인 요청을 제공했다.

| 요청 | 실제 관찰 |
| --- | --- |
| 표시 함수만 짧게 설명 | null·undefined 대체, 문자열 변환·공백 제거와 짧은 예제로 답했다. 다른 기능의 분석 결과를 섞지 않았다. |
| 여러 계층의 흐름 설명 | select → loadRecord → readRecord → transport → JSON 처리 → 캐시 → label → render를 연결했다. |
| 연속 호출·실패 설명 | 화면 갱신 억제와 요청 취소를 구별했고, 오래된 성공도 캐시를 갱신할 수 있음을 설명했다. 캐시 유무에 따른 복구·오류 전파를 구별했다. |
| 상태 소유권 | 요청 번호는 뷰 인스턴스별, 캐시는 모듈 인스턴스별이라고 구별했다. |
| 설계 의도·외부 캐싱 질문 | 의도는 추론으로 표시했고, 서버·통신 구현·응답 헤더가 없어 서버 캐싱은 확인할 수 없다고 답했다. |
| 설명만 요청 | 검증자가 전후 전체 파일 SHA-256, Git index 파일 SHA-256, HEAD를 대조해 모두 같음을 확인했다. 테스트·커밋·외부 게시 도구 호출도 없었다. |
| 유사 스킬 경계 | 표현 교정·결함 판단·코드 설명 역할을 분리했다. 기존 조직 플러그인과 한정 이름이 구별됨을 확인했다. |

이 결과는 실제 답변과 도구 기록을 읽고 코드와 대조한 관찰이다. 문구 일치 테스트를 모델 행동 검증으로 세지 않았다.

같은 새 작업에서 후속 요청도 순서대로 실행했다. `technical-writing`은 조건과 근거가 없는 안전성 단정을 확인 필요로 표시했다. `code-review`는 캐시 갱신 순서의 발생 조건·위치·영향을 보고했고 수정이나 댓글 게시를 실행하지 않았다. `code-explainer`는 설치된 형식 지침과 템플릿을 읽어 허용된 HTML 산출물 하나를 작성했다. 검증자가 생성 문서를 직접 읽어 호출 순서·조건·근거를 대조했고, 별도 로컬 HTTP 미리 보기에서 1440px·390px의 가로 넘침 없음, 목차 위치·현재 절 표시·키보드 펼치기와 스크립트 오류 없음을 확인했다. 문서 작성 작업 자체는 파일 URL 접근 제한으로 브라우저 확인을 못 했다고 정확히 보고했다. 이 후속 HTML 검사는 코드의 실제 통신·경쟁 상태를 실행한 검증과는 다르다. 후속 요청 뒤에도 원본 전체 파일·index·HEAD가 같음을 대조했다.

## 제한

자연어만으로 호출했을 때의 자동 선택 정확도, 모든 모델에서의 반복 재현성, 다른 에이전트, Safari·Firefox와 실제 모바일 기기는 미검증이다. 설치된 조직 플러그인에는 설명 전용 스킬이 없으므로 두 설명 스킬이 동시에 자동 선택 후보가 되는 상황은 검증하지 못했다. 외부 서비스나 게시 기능은 실행하지 않았다. 이 한정된 스모크 검증을 모든 환경의 호환성 보장으로 확장하지 않고 매니페스트의 대상 상태는 `unverified`로 유지한다.
