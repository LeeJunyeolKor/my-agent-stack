<a id="architecture"></a>
# 아키텍처

<a id="system-boundary"></a>
## 시스템 경계

My Agent Stack은 공개 카탈로그이자 결정론적으로 동작하는 로컬 설치 도구입니다. 독립적으로 작성하고 공개에 맞게 정제한 스킬과 자동화 레시피를 패키징한 뒤, 선택한 항목만 기존 프로젝트나 사용자 루트에 설치합니다.

이 프로젝트는 에이전트 마켓플레이스, 외부 커넥터, 스케줄러, 자격 증명 관리자, 에이전트 간 동작 변환기가 아닙니다. 버전 0.1의 프로바이더 항목은 기능 선택 정보만 기록합니다.

```text
카탈로그 + 구성 요소
        │
        ▼
 기능 확인기 ── 호환되지 않는 구성 요소 → 명시적으로 제외
        │
        ▼
 결정론적 계획 ─── 파일을 쓰지 않음
        │ 확인된 설치
        ▼
 에이전트 스킬 경로 + 비활성 자동화 레시피
        │
        ▼
 profile.json + checksum 영수증(receipt.json)
```

<a id="layers"></a>
## 계층

<a id="portable-components"></a>
### 이식 가능한 구성 요소

각 `skills/<id>` 및 `automations/<id>` 디렉터리에는 사람과 에이전트가 읽는 엔트리포인트와 `manifest.json`을 둡니다. 엔트리포인트에는 런타임 지침이 들어 있습니다. 매니페스트에는 설치, 호환성, 기능, 권한, 출처, 포트폴리오 메타데이터가 들어 있습니다.

<a id="agent-targets"></a>
### 에이전트 대상

`catalog/agents.json`은 프로젝트 및 사용자 범위를 각 제품이 문서화한 Agent Skills 디렉터리에 매핑합니다. 여러 제품이 의도적으로 `.agents/skills`를 공유하므로, 계획 생성기는 같은 대상에 설치되는 동일한 복사 작업을 하나로 합칩니다.

대상 상태는 증거 수준을 나타내는 라벨입니다.

- `verified`: 해당 대상에서 현실적인 동작 검증을 통과했습니다.
- `unverified`: 표준 폴더에 설치할 수 있지만 동일한 동작은 아직 입증하지 못했습니다.
- `unsupported`: 해당 대상에는 구성 요소를 설치하면 안 됩니다.

<a id="provider-capabilities"></a>
### 프로바이더 기능

구성 요소는 제품 이름이 아니라 `scm.history.read`, `issue.status.write` 같은 기능을 요청합니다. `catalog/providers.json`은 선택한 프로바이더를 이러한 기능에 매핑합니다. `none`을 선택하는 것도 유효합니다. 필수 기능이 없으면 해당 구성 요소를 제외하고, 선택 기능이 없으면 사용할 수 있는 맥락이 줄어든다는 경고를 표시합니다.

현재 프로바이더는 `profile-only`입니다. SDK를 설치하거나 계정을 인증하거나 외부 API를 호출하지 않습니다.

<a id="installer"></a>
### 설치 도구

CLI는 카탈로그를 불러와 검증하고, 필요한 기능을 확인하고, 모든 원본 파일의 해시를 계산해 결정론적인 계획을 만듭니다. 설치 과정에서는 카탈로그가 소유한 구성 요소 디렉터리만 복사합니다. 기존 내용과 같으면 아무 변경도 하지 않습니다. 내용이 충돌하면 정확한 설치 위치를 검토하고 `--force`를 명시하지 않는 한 실패합니다.

생성된 상태는 `.my-agent-stack/`에 저장됩니다.

- `profile.json`: 선택한 에이전트, 프로바이더, 스킬, 자동화, 설치 범위
- `receipt.json`: 설치한 구성 요소 버전, 대상 위치, SHA-256 해시
- `automations/`: 선택한 레시피. 항상 비활성 상태로 복사됨

<a id="future-extension-points"></a>
## 향후 확장 지점

- 문서화된 API를 통해 필요한 기능을 제공하는 프로바이더 어댑터
- 동일한 스킬 소스에서 생성하는 에이전트별 플러그인 패키지
- 레시피 미리 보기와 활성화를 분리하는 스케줄러 어댑터
- My Workbench가 읽을 수 있는 기계 판독형 피드
- 영수증을 기준으로 동작하는 제거 및 업데이트 기능

이러한 확장 기능도 파일을 쓰기 전 미리 보기, 명시적 권한, 변경 후 검증 계약을 유지해야 합니다.
